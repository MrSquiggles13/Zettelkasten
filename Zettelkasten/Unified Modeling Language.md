# Unified Modeling Language

## Notes

A collection of diagrams that help convey the functionality of a design. This is a standard for visualizing designs and can come in many forms.

**Component Diagrams**
![[Pasted image 20260515022000.png|328]]
Usually used for visualizing the flow of computer programs

**Behavioral Diagrams**
![[Pasted image 20260515022137.png|277]]
Describes the inner workings of a system

**Activity Diagram**
![[Pasted image 20260515022310.png|234]]
A form of Behavioral Diagram and is also known as a flow chart. Usually used for automated systems, shows the sequential activities of a system and can help flesh out unrealized scenarios which can lead to better guards for edge cases.
**Black Dots** are termination points where the system begins or ends functionality
**Open Rectangles** represent an activity or action that can be executed
**Diamonds** are for branching decisions and typically ask a question and can give multiple paths representing different options
**Arrows** show the flow by points towards the next action in the system
